# Lapka

English version: [README.md](README.md)

Локальный аниме-плеер. Вставляете ссылку на аниме или на одну серию, Lapka
читает страницу, находит серии, озвучки, качества и субтитры и показывает всё в
своём плеере. Серии идут одна за другой, выбранная озвучка держится на весь
сериал, любую серию можно сохранить одним файлом в свою папку.

Работает целиком на вашей машине: маленький сервер на Node.js читает страницы
сайта теми же запросами, что сделал бы ваш браузер, и отдаёт видео вашему
браузеру. Наружу ничего не проксируется, аккаунтов и библиотек в облаке нет.

Идея, дизайн и проверка руками: Dimbo. Код написан вместе с Claude в Claude Code.

![Стартовый экран: печать Lapka, поле для ссылки и описание слева](docs/media/home_page.png)

Lapka выросла из [PIP-Player](https://github.com/MythHand/PIP-Player), локального
плеера того же автора под лицензией MIT. Его код переработан свободно и в составе
Lapka идёт под её лицензией; в исходном виде он остаётся доступен в репозитории
PIP-Player под MIT. Уведомление MIT сохранено в
[LICENSES/PIP-Player.MIT.txt](LICENSES/PIP-Player.MIT.txt).

## Что умеет

- **Очередь.** Серии всех сезонов, фильмов и спин-оффов франшизы в порядке выхода, даже когда
  сайт держит все сезоны в одном плеере.
- **Озвучки.** Переключение на ходу, без перезагрузки; выбор запоминается на всю франшизу,
  другой сезон стартует в той же озвучке.
- **Озвучки по частям.** Карта «части × серии» кнопкой в шапке очереди и в меню озвучки: у каких
  серий какие озвучки есть, наведение подсвечивает.
- **Качество.** Любой вариант источника, включая уровни внутри одного потока.
- **Субтитры.** Отдельной дорожкой, когда источник их отдаёт; вид субтитров настраивается.
- **Заставки.** Кнопка пропуска, если сайт знает тайминги; можно и автоматически, с шестью
  секундами на «смотреть».
- **Продолжение.** С того места, где остановились, для каждой серии, какая бы ни была озвучка;
  досмотренная серия отмечается, на кадре видно, где остановились, а на шкале — что уже лежит
  на диске.
- **Пауза.** На паузе кадр показывает сериал: обложка, год, тип, сколько серий, жанры, студия,
  первоисточник, возраст и озвучки этой части. Выключается в настройках.
- **История.** Вставленные ссылки под рукой: поле ссылки в подвале очереди по фокусу открывает
  историю и ищет по ней, по названию или адресу; справа — части франшизы с обложкой, годом и
  числом серий. У каждой ссылки видно, где остановились, и открывается она с того места; лишняя
  убирается из списка.
- **Сохранение.** Серия одним файлом в вашу папку, с выбранной озвучкой и субтитрами внутри.
  Загрузки идут очередью, одна за другой: пауза держит серию на достигнутом месте и продолжает
  оттуда, ожидающую можно сделать текущей, любую отменить, сохранённые файлы удалить из
  библиотеки прямо из плеера. Прерванное сохранение доделывается само. Качество для сохранения
  группы: максимальное, как в плеере или ближайшее к названному. Сохранённая серия играет с
  диска, в сеть за ней Lapka не ходит; в меню озвучки у такой озвучки пометка «на диске».
- **Источники.** Несколько плееров на серию; мёртвый источник меняется на живой сам.
- **Журнал.** Пока страница читается, разбор виден по шагам: что нашла, какие плееры открыла,
  какие части франшизы собрала.
- **Папка.** Сохранённые видео, заметки Lapka и кэш видны в настройках с размерами и чистятся
  каждое отдельно.
- **Обновление.** Из настроек: проверка версии на GitHub по кнопке, обновление и перезапуск
  самой Lapka, для папки-клона и для скачанного ZIP.
- **Отдельное окно.** Картинка в картинке, в том числе расширенная, с управлением прямо в окне.
- **Десять языков интерфейса.**

Механизм разбора страниц общий, а не написанный под конкретные сайты: Lapka ищет
плееры, списки серий и озвучек по устройству страницы. Проверено на:
aniliberty.top, old.yummyani.me, jut-su.net, animego.me, anidubonline.ru,
gogoanime.by, jkanime.net, newdeaf.co, yummyanime.tv, ani-media.online,
domanime.ru, lordserials.fan, ailiberty.top. Другие сайты с похожим устройством чаще всего
открываются тоже. Сайты с DRM и сайты, которые намеренно закрывают
свои плееры, Lapka не вскрывает.

## Приложение для macOS

Ветка поддерживает сборку `Lapka.app` для macOS 13.5 и новее. Распакуйте
`Lapka-macos-arm64.zip` (Apple Silicon) или `Lapka-macos-x64.zip` (Intel),
перенесите `Lapka.app` в «Программы» и откройте иконку. Приложение содержит
Node.js и открывает плеер в собственном окне WebKit: терминал, npm и отдельный
браузер для запуска не нужны. Релизная сборка публикует DMG и ZIP в
[Releases](https://github.com/MythHand/Lapka/releases).

Закрытие окна оставляет приложение в Dock; повторное открытие иконки возвращает
окно. `⌘Q`, меню **Lapka → Quit Lapka** и кнопка выхода в настройках завершают
приложение и его сервер. Сервер приложения использует `127.0.0.1:18800`;
занятый порт показывается как ошибка, чужой процесс не завершается.

Во время просмотра системные кнопки окна скрываются вместе с управлением плеера.
Наведите мышь к верхнему краю, чтобы вернуть их. На паузе и при открытых меню
кнопки видимы; в полноэкранном режиме ими управляет macOS.

Настройки и исходная папка библиотеки находятся в
`~/Library/Application Support/Lapka`, журнал — в `~/Library/Logs/Lapka/server.log`.
Папку с видео можно поменять в настройках. Удаление или обновление `.app` не
удаляет библиотеку. Для сохранения видео по-прежнему нужен отдельно установленный
ffmpeg; просмотр работает без него. Расширенное Document PiP доступно в браузерах
Chromium, а не в окне WebKit; в приложении работает системное видео PiP.
Для него используется проверяемая перед включением частная настройка WebKit:
публичный переключатель Apple предоставляет только для iOS. При изменении этого
API в будущей macOS поддержку потребуется пересмотреть.
Передачу на настоящий AirPlay-приёмник ещё нужно проверить.

Перед пересборкой закройте приложение, запущенное из папки результата.
Сборка на Mac с Node.js 22+ и Xcode Command Line Tools:

```bash
npm ci
npm run build:macos
npm run test:macos
```

Результат: `dist/macos-arm64/Lapka.app` и ZIP рядом (на Intel — `macos-x64`).
Отдельная команда `npm run build:dmg` упаковывает готовое приложение в образ
`Lapka-1.3.0-macos-arm64.dmg` рядом с `.app`. Внутри — ссылка на «Программы»
для установки перетаскиванием. Имя файла содержит версию и архитектуру готовой
сборки, а название тома — её версию. Изменение версии в исходниках не меняет
маркировку уже собранного приложения.
Приложение проверяет наличие новых версий; обновление устанавливается заменой
`.app` или через DMG, без перезаписи файлов внутри подписанного приложения.
Для другого пути к приложению или папки результата:
`npm run build:dmg -- --app=/путь/Lapka.app --output-dir=/путь/releases`.
При упаковке DMG закрывать приложение не нужно.

Публикация GitHub Release запускает **macOS release** для Apple Silicon и Intel.
Workflow берёт исходники из тега релиза и заново собирает приложение, DMG и ZIP
на каждой архитектуре. Версия тега (например, `v1.3.0` или `1.3.0`) должна
совпадать с `package.json`. После успеха обеих сборок DMG, ZIP и контрольные
суммы SHA-256 прикрепляются к релизу. Артефакты Actions дополнительно хранятся
30 дней. Для пересборки существующего релиза запустите workflow вручную с его
тегом. В коммите тега уже должны быть скрипты macOS-сборки и этот workflow.

Для обновления проверьте версию в настройках, скачайте новый DMG для своего Mac,
закройте Lapka через `⌘Q` и перенесите новое приложение в «Программы» с заменой
старого. Библиотека и настройки хранятся вне приложения и сохранятся.
Установка обновлений пока выполняется вручную.

Сборщик загружает официальный Node.js 24.13.0 и проверяет SHA-256 архива.
Для сборки без загрузки runtime: `npm run build:macos -- --node=/полный/путь/bin/node`;
рядом с `bin/` должен лежать `LICENSE` Node либо укажите `--node-license=/путь/LICENSE`.
Для Intel доступен `--arch=x64`; проверка runtime требует возможности запустить
выбранную архитектуру на сборочной машине.

Локальные и CI-сборки пока используют ad-hoc подпись без notarization.
Релизные файлы помечены как экспериментальные: Gatekeeper может блокировать
первый запуск после скачивания. Для обычного публичного распространения ещё
нужно настроить Developer ID и notarization; `LAPKA_SIGN_IDENTITY` задаёт
подпись сборщика.

## Ресурсы

Видео декодирует браузер; Lapka пропускает через себя куски по одному-два
мегабайта и пишет их на диск, поэтому процесс остаётся лёгким. Место на диске
занимают сохранённые серии и кэш, и то и другое в ваших руках.

| | Память | Процессор | Диск |
|---|---|---|---|
| Процесс Node, запуск | 75 МБ | ~0% | — |
| Процесс Node, после часов просмотра | 80 МБ | ~0% | — |
| ffmpeg при сохранении серии | до 60 МБ | одно ядро на 2–3 с на серию в 24 минуты | файл серии; размер задаёт источник, не разрешение: серия в 24 минуты обычно около 200 МБ |
| Заметки Lapka: 30 ссылок в истории с обложками частей, 100 мест остановки, 400 отметок досмотренного | — | — | 22 МБ, из них 108 КБ сам файл, остальное обложки |
| Кэш | — | — | до лимита из настроек, старое чистится само |
| Сохранённые серии | — | — | сколько сохранили |

## Запуск в браузере

Нужны [Node.js](https://nodejs.org/) 22 или новее (проверено на 24) и, только
для сохранения серий в файл, [ffmpeg](https://ffmpeg.org/) в PATH. Смотреть можно
и без ffmpeg.

Самый короткий путь, без скачивания и без папки:

```bash
npx -y lapka
```

npx скачает Lapka в кэш npm, запустит и откроет в браузере; следующий такой
запуск возьмёт новую версию сам.

С папкой проекта:

```bash
git clone https://github.com/MythHand/Lapka.git
cd Lapka
npm install
npm start
```

Откройте http://127.0.0.1:8800 в браузере. Рекомендуется Chrome или Edge:
расширенное окно картинки в картинке есть только у них; в Firefox и Safari
всё остальное работает, а картинка в картинке обычная. Остановить сервер:
Ctrl+C в терминале.

Или без терминала: `start.command` на macOS и `start.bat` на Windows открываются
двойным кликом, `./start.sh` на Linux. Каждый проверяет Node.js, при первом запуске
ставит недостающее, поднимает Lapka в фоне и открывает её в браузере; это окно потом
можно закрыть, Lapka продолжает работать. Выключить: `stop.command`, `stop.bat` или
`./stop.sh`, либо кнопка «Выключить Lapka» в настройках (лапка в правом верхнем углу).
Обновить: в настройках строка «Версия» → «Проверить обновление» → «Обновить до v…»,
Lapka скачает, установит и перезапустится сама; или `update.command`, `update.bat`,
`./update.sh` (не второй `git clone`: git не пишет в существующую папку).
Что менялось от выпуска к выпуску: [CHANGELOG.ru.md](CHANGELOG.ru.md).

![Настройки: статус и версия, интерфейс, плеер, хранение с папкой, сохранёнными видео, заметками и кэшем, горячие клавиши](docs/media/setting.png)

Файлы Lapka складываются в папку, которую вы выбираете в настройках
(лапка → «Папка Lapka»). До первого выбора это `.dev/home` внутри папки
проекта, а при запуске через npx папка `Lapka` в вашей домашней папке. Сам
выбор хранится в системной папке настроек пользователя, один для всех способов
запуска. Переменная окружения `LAPKA_HOME` задаёт папку принудительно, `PORT`
меняет порт.

## AirPlay (экспериментально)

В Safari на Mac откройте серию и нажмите кнопку AirPlay рядом с кнопкой
картинки в картинке, затем выберите Apple TV или телевизор с AirPlay.
Компьютер с Lapka и телевизор должны находиться в одной локальной сети;
Lapka должна продолжать работать, а компьютер — оставаться включённым.
Если macOS спросит о входящих подключениях Node.js, разрешите их для своей сети.
В браузерах без API AirPlay кнопка скрыта.

Передача переключает видео на нативное воспроизведение Safari с сохранением
позиции и паузы. Для нескольких озвучек в одном HLS-потоке передаётся выбранная
озвучка; качеством внутри адаптивного потока во время AirPlay управляет приёмник.
Оформленный поверх видео слой субтитров Lapka на телевизор не передаётся.

При подготовке потока в Safari Lapka открывает отдельный порт на сетевом IPv4-адресе.
Он отдаёт только выбранное видео по случайной ссылке с токеном; настройки и
остальные API остаются на localhost. Ссылка отзывается при смене или остановке
источника и истекает через 24 часа. Если выбрана неверная сетевая карта, задайте
её адрес явно: `LAPKA_AIRPLAY_HOST=192.168.1.10 npm start` (пример адреса).

Покрыты HTTP-прокси и поведение плеера с имитацией Safari API в Chrome.
Подключение к настоящему AirPlay-приёмнику, переход между сериями и поведение
конкретных телевизоров ещё требуют проверки в Safari на устройстве.

## Если вы не разработчик

Коротко: поставить Node.js с [nodejs.org](https://nodejs.org/) (кнопка LTS),
скачать этот проект (зелёная кнопка **Code** → **Download ZIP**), распаковать,
дважды кликнуть `start.command` (macOS) или `start.bat` (Windows). Браузер
откроет Lapka сам.

Подробно и по шагам для macOS, Windows и Linux, включая ffmpeg и типичные
ошибки: [docs/INSTALL.ru.md](docs/INSTALL.ru.md). Если ставите с помощью
ИИ-ассистента, дайте ему ссылку на этот файл: там всё, что нужно для точного
ответа.

## Разработка

Как запускать Lapka, сказано в двух разделах выше: «Запуск» это запуск
разработчика из клона (`git clone`, `npm install`, `npm start`), «Если вы не
разработчик» это установка из ZIP с лончером. Здесь ни то ни другое: здесь
инструменты для работы над кодом Lapka, для просмотра они не нужны.

- `npm run dev` — Lapka на 8800 и синтетический сайт для тестов на 8801: подставной
  «сайт с аниме» из `test/site`, на котором проверяется общий разбор страниц. Его
  клипы собирает ffmpeg; без него поднимется только Lapka.
  `SITE_SLOW_MS=3000 npm run site` замедляет отдачу файлов синтетического сайта, чтобы
  руками проверять паузу и очередь сохранений.
- `npm test` — все тесты. `npm run check` — статическая проверка фронта.
  Тесты реальных сайтов вместе со снимками их страниц хранятся вне репозитория.
- Карта ядра и контракты блоков: [core/README.ru.md](core/README.ru.md).

## Границы

Lapka нейтральна: это инструмент на вашей машине, который читает открытые
страницы вашими же запросами. Она не обходит DRM, не проксирует трафик наружу
и не хранит ничьи данные. Ответственность за то, что и где вы смотрите, на вас.
